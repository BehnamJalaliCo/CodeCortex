# Governance

CodeCortex currently uses a maintainer-led governance model appropriate for an early-stage open-source project.

## Maintainer

The repository owner and lead maintainer is `@BehnamJalaliCo`. The lead maintainer is responsible for release decisions, security response, architecture direction, repository administration, and appointing future maintainers.

## Decision making

Routine changes are decided through review and automated checks. Significant architecture, compatibility, security, governance, or licensing changes should include a written rationale in the pull request or an issue before merge.

When consensus is not available, the lead maintainer makes the final project decision and should document the reasoning when the decision materially affects contributors or users.

## Maintainer expectations

Maintainers are expected to review contributions fairly, protect confidential security reports, avoid undisclosed conflicts of interest, enforce the Code of Conduct consistently, and keep releases reproducible.

## Becoming a maintainer

Sustained high-quality contributions, sound technical judgment, respectful collaboration, and demonstrated security awareness are the primary signals for maintainer access.

## Changes to governance

Governance changes are made in public through version-controlled changes to this file.
